Start a run

Pick a recon spec and a dataset, choose which model runs the investigation agent, and go. The spec is a YAML file — sources, keys, tolerances, the settlement identity, the taxonomy, the rules. The engine is generic; the spec is the logic.

🔑  Bring your own API key — provider, key and model are stored only in this browser and sent with each run

This walkthrough is a replay of a real run, so the key isn't used here. In the live cockpit (make up) the key rides an X-LLM-Key header on POST /v1/runs and is used for that run only — never written to disk or the event log.

        stop 07

        What runs where

        The cockpit is a standard server-rendered web app talking to a REST + SSE API. Anything with a modern browser reaches it; the hosting side is Linux containers.

        This page

        Self-contained HTML — Windows, macOS, Linux, iOS Safari, Android Chrome, tablets. No backend, no build. It is what you're looking at now.

        The real cockpit — clients

        Next.js 15 SSR + React 19. Any browser from the last ~3 years: Chrome, Safari, Firefox, Edge, mobile Safari & Chrome. Now responsive down to 360 px (three surfaces → tabs), keyboard-first on desktop, prefers-reduced-motion and full light/dark honoured.

        The engine & API

        Python 3.12 · FastAPI · SQLite for the demo, Postgres for real. make demo on any Mac/Linux box; Docker image is linux/amd64 + arm64.

        CLI

        arbiter run · bench · explain · replay · verify · memo · cash-position — cross-platform Python, --json on every command, NO_COLOR respected.

        Deploy

        Helm chart (api / worker / web / pgbouncer / redis), HPAs, a pre-upgrade migration hook. Any CNCF-conformant Kubernetes ≥ 1.28. Per-PR preview envs.

        Not yet

        Native mobile apps (none planned — the responsive web cockpit is the mobile story). Offline mode. IE / pre-2021 browsers.

        Run the real thing: git clone …/Arbiter- && make demo then make up → API on :8000, cockpit on :3000.
